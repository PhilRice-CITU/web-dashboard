# hum.ai Documentation Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone, MDX-powered documentation site to `web-dashboard` — grouped sidebar nav, centered content, right-side TOC, search, and dark mode — that opens in a new tab from the dashboard's "Documentation" link.

**Architecture:** A new top-level TanStack route tree (`/docs`, outside the authenticated app shell) renders a `DocsLayout` (3-column, single flat background, max-width 1120px). Doc pages are `.mdx`/`.md` files compiled by `@mdx-js/rollup`, discovered via `import.meta.glob`, ordered by a `docs.config.ts` nav tree. Operator-guide content is drafted fresh; technical-reference content is synced from the sibling `docs-and-architecture` repo by a script.

**Tech Stack:** React 19, TanStack Start/Router, Vite 7, Tailwind v4 + shadcn/ui, MDX (`@mdx-js/rollup`, `@mdx-js/react`), `remark-gfm`, `remark-frontmatter`, `remark-mdx-frontmatter`, `rehype-slug`, `rehype-highlight`. Tests: Vitest + Playwright.

**Spec:** `docs/superpowers/specs/2026-05-21-docs-page-design.md`

**Conventions:**

- Path alias: `#/*` → `./src/*` (e.g. `import { Button } from '#/shared/components/ui/button'`).
- All colors use existing CSS variable tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-accent`, …). Never hard-code hex.
- The pre-commit hook runs ESLint + Prettier + `vite build`. Each commit triggers it; if it auto-fixes, re-stage and commit again.
- Run unit tests with `npm run test` (Vitest, single run). Component/DOM tests opt into jsdom with a `// @vitest-environment jsdom` docblock at the top of the test file.
- **Type-check scope:** the project has ~13 pre-existing `tsc --noEmit` errors in unrelated features (devices, results, analytics, landing, scroll-area) — these are out of scope; do not fix them. When a task says "Run `npx tsc --noEmit` — Expected: no errors", verify only that the docs feature is clean: `npx tsc --noEmit 2>&1 | grep -E 'features/docs|routes/docs|content/docs'` must print nothing.

- [ ] **Step 1: Write the sync script**

Create `scripts/sync-docs.mjs`:

```js
// Syncs technical-reference markdown from the sibling docs-and-architecture repo.
// Run: npm run sync:docs
import { readFile, writeFile, mkdir } from 'node:fs/promises'
import { existsSync } from 'node:fs'
import { dirname, join, resolve } from 'node:path'
import { fileURLToPath } from 'node:url'
import { execSync } from 'node:child_process'

const root = dirname(dirname(fileURLToPath(import.meta.url)))

// docs-and-architecture sits beside the MAIN repo checkout. Resolve the main
// repo via git's common dir so this also works when run from a git worktree.
let mainRepo
try {
  const gitCommonDir = execSync('git rev-parse --git-common-dir', {
    cwd: root,
    stdio: ['ignore', 'pipe', 'pipe'],
  })
    .toString()
    .trim()
  mainRepo = dirname(resolve(root, gitCommonDir))
} catch {
  console.error(
    'sync-docs: could not resolve the git common dir. Run this from inside the web-dashboard repo.',
  )
  process.exit(1)
}

const SRC = join(mainRepo, '..', 'docs-and-architecture', 'api-server')
const DEST = join(root, 'src', 'content', 'docs', 'technical-reference')

/** source file → { target, title, description } */
const FILES = {
  'architecture.md': {
    target: 'api-architecture.md',
    title: 'API architecture',
    description: 'FastAPI request flow: routers, services, repositories.',
  },
  'database-schema.md': {
    target: 'database-schema.md',
    title: 'Database schema',
    description: 'Supabase Postgres tables, relationships, and RLS policies.',
  },
  'grading-pipeline.md': {
    target: 'grading-pipeline.md',
    title: 'Grading pipeline',
    description: 'YOLO inference and PNS 290:2025 grading internals.',
  },
  'metrics-contract.md': {
    target: 'metrics-contract.md',
    title: 'Metrics contract',
    description: 'Canonical shape of the results.metrics JSON payload.',
  },
  'device-events-operations.md': {
    target: 'device-events.md',
    title: 'Device events & operations',
    description: 'Event tiers, retention windows, and operational notes.',
  },
}

await mkdir(DEST, { recursive: true })

let synced = 0
for (const [srcName, cfg] of Object.entries(FILES)) {
  const srcPath = join(SRC, srcName)
  if (!existsSync(srcPath)) {
    console.warn(`! skipped (not found): ${srcPath}`)
    continue
  }
  const body = await readFile(srcPath, 'utf8')
  // Quote the YAML scalars — titles/descriptions may contain colons.
  const frontmatter = `---\ntitle: "${cfg.title}"\ndescription: "${cfg.description}"\n---\n\n`
  await writeFile(join(DEST, cfg.target), frontmatter + body, 'utf8')
  console.log(`✓ ${srcName} → technical-reference/${cfg.target}`)
  synced++
}
console.log(`\nSynced ${synced}/${Object.keys(FILES).length} files.`)
```

```mdx
description: An overview of the hum.ai grading pipeline and PNS 290:2025.
---

hum.ai grades milled rice automatically using computer vision, following the
**PNS/BAFS 290:2025** Philippine National Standard for milled rice.

## The pipeline

1. An edge device captures images of a rice sample under controlled lighting.
2. The AI model detects individual grains and classifies their defects.
3. Defect counts are measured against the PNS thresholds.
4. A single overall **quality grade** is assigned and stored as a result.

## Why it is consistent

Because every sample runs through the same model and the same PNS thresholds,
grading does not depend on a human inspector — the same rice produces the same
grade every time.

## Learn more

- [Quality grades](/docs/grading-and-standards/quality-grades) — what each grade means.
- [Defect types](/docs/grading-and-standards/defect-types) — the defects the model detects.
```

```mdx
description: How hum.ai assigns an overall PNS quality grade.
---

Every graded scan receives one overall **quality grade** derived from the
defects found in the sample.

## How the grade is decided

The pipeline measures each defect type as a percentage of the sample, then
compares those percentages to the PNS/BAFS 290:2025 thresholds. The grade
reflects the **worst** category the sample still satisfies — a single
out-of-threshold defect can lower the overall grade.

## Reading a grade

On a result, the quality grade is shown alongside the metrics that produced it,
so you can see which defect drove the outcome. A lower grade is not an error —
it is an accurate measurement of the sample.
```

```ts
describe('docs.config', () => {

    expect(flat[0]).toBe('getting-started/introduction')
```

```ts
  eager: true,
})

/** Convert a glob path to a slug: ".../getting-started/intro.mdx" → "getting-started/intro". */
function pathToSlug(path: string): string {
  return path.slice(PREFIX.length).replace(/\.(md|mdx)$/, '')
}

const registry = new Map<string, DocMeta>()

  const slug = pathToSlug(path)
  const fm = mod.frontmatter
  if (!fm?.title) {
    console.warn(`[docs] "${slug}" is missing frontmatter title — skipped.`)
    continue
  }
  registry.set(slug, {
    slug,
    title: fm.title,
    description: fm.description ?? '',

  })
}

  return registry.has(slug)
}
```

```ts
import { useCallback, useEffect, useState } from 'react'

type Theme = 'light' | 'dark'
const STORAGE_KEY = 'theme'

function getInitialTheme(): Theme {
  if (typeof window === 'undefined') return 'light'
  const stored = window.localStorage.getItem(STORAGE_KEY)
  if (stored === 'light' || stored === 'dark') return stored
  return window.matchMedia('(prefers-color-scheme: dark)').matches
    ? 'dark'
    : 'light'
}

function applyTheme(theme: Theme) {
  document.documentElement.classList.toggle('dark', theme === 'dark')
}

/** Global light/dark theme, persisted to localStorage and applied to <html>. */
export function useDocsTheme() {
  const [theme, setTheme] = useState<Theme>(getInitialTheme)

  useEffect(() => {
    applyTheme(theme)
    window.localStorage.setItem(STORAGE_KEY, theme)
  }, [theme])

  const toggleTheme = useCallback(() => {
    setTheme((t) => (t === 'dark' ? 'light' : 'dark'))
  }, [])

  return { theme, toggleTheme }
}
```

```ts
import { useEffect, useState } from 'react'
import type { RefObject } from 'react'
import type { TocItem } from '../types'

/**
 * Extracts h2/h3 headings from a rendered content container and tracks the
 * heading currently in view (scroll-spy). `deps` re-runs extraction when the
 * page changes (pass the current slug).
 */
export function useTableOfContents(
  containerRef: RefObject<HTMLElement | null>,
  deps: unknown[] = [],
): { items: TocItem[]; activeId: string | null } {
  const [items, setItems] = useState<TocItem[]>([])
  const [activeId, setActiveId] = useState<string | null>(null)

  // Collect headings whenever the content changes.
  useEffect(() => {
    const el = containerRef.current
    if (!el) return
    const headings = [...el.querySelectorAll('h2, h3')].filter(
      (h): h is HTMLHeadingElement => h.id !== '',
    )
    setItems(
      headings.map((h) => ({
        id: h.id,
        text: h.textContent ?? '',
        level: h.tagName === 'H2' ? 2 : 3,
      })),
    )
    setActiveId(headings[0]?.id ?? null)
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, deps)

  // Scroll-spy: highlight the top-most heading currently on screen.
  useEffect(() => {
    if (items.length === 0) return
    const observer = new IntersectionObserver(
      (entries) => {
        const visible = entries
          .filter((e) => e.isIntersecting)
          .sort((a, b) => a.boundingClientRect.top - b.boundingClientRect.top)
        if (visible[0]) setActiveId(visible[0].target.id)
      },
      { rootMargin: '0px 0px -70% 0px', threshold: 0 },
    )
    for (const item of items) {
      const node = document.getElementById(item.id)
      if (node) observer.observe(node)
    }
    return () => observer.disconnect()
  }, [items])

  return { items, activeId }
}
```

```ts
import type { DocSearchEntry } from '../types'
import { docsNav, getSectionLabel } from '../docs.config'
import { getDoc } from './docs-registry'

/** Build the client-side search index from the nav config + registry. */
export function buildSearchIndex(): DocSearchEntry[] {
  const entries: DocSearchEntry[] = []
  for (const section of docsNav) {
    for (const slug of section.items) {
      const doc = getDoc(slug)
      if (!doc) continue
      entries.push({
        slug,
        title: doc.title,
        description: doc.description,
        section: getSectionLabel(slug) ?? '',
      })
    }
  }
  return entries
}

/** Case-insensitive substring filter over title + description + section. */
export function searchDocs(
  index: DocSearchEntry[],
  query: string,
): DocSearchEntry[] {
  const q = query.trim().toLowerCase()
  if (q === '') return index
  return index.filter((e) =>
    `${e.title} ${e.description} ${e.section}`.toLowerCase().includes(q),
  )
}
```

## Notes for the implementer

- **Token colors only** — every component uses Tailwind classes bound to the CSS
  variables (`bg-background`, `text-muted-foreground`, `border-border`,
  `bg-accent`, …). This is what makes dark mode and brand-consistency automatic.
  Never introduce a hex value in a component.
- **`cn` helper** — imported from `#/shared/lib/utils`. Confirm the path by
  checking an existing `src/shared/components/ui/*.tsx` file; match it.
- **Route types** — TanStack regenerates `src/routeTree.gen.ts` when `npm run dev`
  runs. If `tsc` reports unknown routes, run the dev server once to regenerate.
